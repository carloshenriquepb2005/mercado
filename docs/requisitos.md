# Requisitos

- O atendente deve conseguir entrar com `nome` e `senha` da tabela `usuarios`, visualizar a Home e a disponibilidade da API e escolher entre consulta de estoque, alteração de preço e entrada no estoque. A consulta de estoque permite escanear ou digitar um código numérico de até 13 caracteres e exibe código do produto, descrição, preço unitário, código NCM e quantidade atual em estoque, sem uma linha independente para unidade e sem permitir alterações. A alteração de preço permite modificar somente o preço unitário, confirmar a operação e consultar seu resumo na tela de Sucesso. A entrada no estoque permite escanear ou digitar o código, exibe código, descrição, unidade, preço unitário, preço de custo e estoque atual, e recebe a quantidade comprada, o novo preço de custo e, opcionalmente, a data de vencimento; após salvar, a tela de Sucesso mostra estoque e custo anteriores e atuais. Se a gravação falhar sem confirmação, o app recarrega o produto, limpa a quantidade e só permite novo envio depois de nova confirmação, para evitar entrada duplicada. Os perfis 1, 2 e 3 possuem o mesmo acesso ao app.

- O sistema deve preservar zeros à esquerda, buscar códigos principais antes dos similares, retornar mensagens amigáveis e impedir múltiplos envios. Não há acesso direto do aplicativo ao MySQL.

- Na primeira abertura, o aplicativo deve exigir um IPv4 de servidor validado antes de liberar o login. A URL fica persistida somente no aparelho e pode ser alterada em Ajustes após validação de `senha.SENHA_CAIXA`. A senha do caixa não é persistida e a autorização é consumida ao abrir a tela protegida. No acesso interno, a conexão salva é verificada automaticamente, sem exibir o redirecionamento para o login, e qualquer teste expira depois de sete segundos.

- O login simples consulta a tabela legada `usuarios` por `nome` e `senha`, sem hash, e aceita igualmente os perfis 1, 2 e 3. O aplicativo guarda somente código, nome e perfil na sessão local; a senha não é persistida. Esse acesso funciona como controle de entrada da interface e não adiciona token aos endpoints de produto. A tabela de usuários é somente leitura.

- A API resolve primeiro `produtos.CODIGO_PRODUTO`; caso não encontre, resolve `produtos_similares.CODIGO_SIMILAR` para o código principal. A consulta retorna `CODIGO_PRODUTO`, `DESCRICAO`, `UN`, `PRECO_UNITARIO`, `CODIGO_NCM` e `ESTOQUE_ATUAL`. As únicas escritas são transações pelo `ID`: a alteração de preço, que altera somente `produtos.PRECO_UNITARIO`, e a entrada no estoque, que altera `ESTOQUE_ATUAL` (soma atômica), `PRECO_CUSTO`, `DATA_ATUALIZACAO` e, somente quando informada pelo usuário, `DATA_VENCIMENTO`; `DATA_ATUALIZACAO` e `DATA_VENCIMENTO` são somente escritas. As demais consultas são somente leitura.
